//------------------------------------------------------------
// Cascade Shadow Mapping (CSM) 개요
//------------------------------------------------------------

대규모 씬에서 그림자 품질을 효율적으로 관리하기 위한 기법
단순 Shadow Mapping의 perspective aliasing 문제를 해결
perspective aliasing: 카메라와 가까운 그림자가 뭉개지거나 계단 현상이 심하게 나타나는 현상


//------------------------------------------------------------
// CSM 핵심 아이디어
//------------------------------------------------------------

View Frustum을 여러 개의 구간(Cascade)로 분할하고, 각 구간마다 별도의 Shadow map 생성

예시) 4단계 CSM
Cascade 0: 0 ~ 10m
Cascade 1: 10 ~ 50m
Cascade 2: 50 ~ 100m
Cascade 3: 100m 이상

1. Sub-frustum의 8개 코너 계산 (world space)
2. 코너들을 감싸는 bounding sphere 또는 bounding box 계산
3. Light 방향으로 orthographic projection matrix 생성


//------------------------------------------------------------
// Frustum 분할 알고리즘 (Split Schemes)
//------------------------------------------------------------

어떤 수학적 방식으로 구간을 나눌 것인지에 대한 알고리즘

Uniform Split: 카메라와 near/far 평면 사이를 일정한 간격으로 분할.
(원거리 낭비가 심해 잘 안쓰임)

Logarithmic Split: 시야에서 멀어질수록 구간을 기하급수적으로 넓게 분할.
(수학적으로 이상적이나 가까운 곳에 너무 많은 해상도가 집중될 수 있음)

Practical Split Scheme (PSSM): Uniform과 Logarithmic 방식의 가중치 평균을
사용하여 실용적인 분할 지점을 찾는 방식. (가장 많이 쓰이는 방식)


//------------------------------------------------------------
// 그림자 깜빡임 (Shimmering / Flickering) 방지
//------------------------------------------------------------

카메라가 회전하거나 이동할 때 그림자 외곽선이 지글거리는 현상을 해결하는 필수 기법

Sub-texel Snapping: 카메라 이동 시 Light View의 Projection Matrix가 연속적으로 변하지 않고, 
섀도우 맵의 텍셀(Texel) 크기 단위로 딱딱 끊어서 이동하게(Snap) 만들어 텍셀의 픽셀 매칭을 안정화하는 기법.

Bounding Sphere 안정화: Sub-frustum의 코너를 기준으로 Bounding Box를 만들면 
카메라 회전 시 크기가 변하므로, 항상 일정한 크기를 유지하는 Bounding Sphere를 사용해 안정화.


//------------------------------------------------------------
// Cascade 경계면 블렌딩 (Cascade Blending)
//------------------------------------------------------------

서로 다른 해상도를 가진 Cascade 구간이 만나는 경계선(Seam)이 눈에 띄게 
단절되는 현상을 부드럽게 이어주는 방법

Dithered Blending: 노이즈 텍스처를 사용해 픽셀 단위로 어떤 Cascade를 샘플링할지 섞는 방식.

Linear Blending (Transition Band): 두 Cascade가 겹치는 좁은 구간을 설정하고, 
거리에 따라 두 개의 섀도우 맵을 샘플링하여 선형 보간(Lerp)하는 방식. (성능 비용이 약간 더 발생)


//------------------------------------------------------------
// 그림자 아티팩트(Artifact) 및 바이어스 (Bias)
//------------------------------------------------------------

단순 Shadow Mapping에서도 발생하지만, CSM에서는 Cascade마다 
텍셀 밀도가 다르기 때문에 Bias를 다르게 적용해야 함

Shadow Acne: 표면이 스스로 그림자를 드리우는 얼룩무늬 현상.

Peter Panning: 그림자와 물체가 붕 떠서 분리되어 보이는 현상 (Bias가 너무 클 때 발생).

해결책: * Constant Depth Bias: 깊이 값에 고정된 오프셋을 줌.

Slope-Scaled Depth Bias: 표면의 기울기(Light와의 각도)에 비례하여 Bias 적용.

Normal Offset Bias: 물체의 Normal 방향으로 위치를 살짝 밀어서 그림자를 계산하는 방식 (가장 시각적 결과가 좋음).


//------------------------------------------------------------
// 메모리 구조 및 성능 최적화
//------------------------------------------------------------

Texture Array (텍스처 배열): Cascade 맵들을 하나의 텍스처 아틀라스로 만들지, 
텍스처 배열(Texture2DArray)로 관리할지에 대한 구조 결정. (최신 API에서는 Texture Array를 선호)

Cascade Culling: 각 Cascade의 View Frustum에 해당하는 오브젝트만 추려내어(Frustum Culling) 
섀도우 맵을 그릴 때 발생하는 Draw Call을 최소화.
