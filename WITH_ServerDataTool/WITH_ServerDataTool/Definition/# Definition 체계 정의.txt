
# Definition 정의 - Version 1

Definition 정의 규칙
 1. Definition은 순수 불변 데이터
 2. Definition간 참조는 ID만 사용하도록 한다.
 3. Root Definition은 독립 ID를 가진다.
 4. 하위 Definition은 상위 Definition 내부 값 객체로 구성한다.



1. Character 계열
 - CharacterDef : CharacterId
	- CharacterProfileDef
	- CharacterStatDef
	- CharacterAIDef (optional)

A. 식별
 - 이 캐릭터가 누구인가

 1) enum CharacterId : 주 식별자 != None
 2) string Name : 보조 식별자 != None


B. 분류 / 소속 - CharacterProfileDef
 - 어떤 진영 / 계열인지

 1) enum Faction : (ex. Neutral, Player, Enemy etc.) != None


C. 기본 능력치 - CharacterStatDef
 1) MaxHp > 0
 2) MaxStamina > 0
 3) AttackPower > 0
 4) Defense > 0
 5) MoveSpeed >= 0
 6) AttackSpeed > 0


D. AI 구성 - CharacterAIDef (optional)
 1) AIArchetype : (Humanoid, NormalMonster, Boss etc.) != None
 2) AITuningId (optional)


-------------------------------------------------------------------------------------------------

2. Action 계열
 - ActionDef : ActionId
	- EndPolicyDef
	- RequestRequirementDef[]
	- ResourceCostDef[]
	- TransitionRuleDef
		- InterruptRules[]
		- CancelRules[]
	- CombatWindowDef[]
	- ActionEventDef[]
	- ActionMovementSegmentDef[]

A. 식별
 - 이 액션은 누구의 어떤 행동인가

 1) ActionId - 주 식별자
 2) Name - 보조 식별자
 3) CharacterId - 이 액션을 가지는 Character
 4) ActionKind - 상위 상태 (Attack, Dodge, Guard 등)
 5) PlayerActionInput - 플레이어 입력 하위 상태(Light_Attack, Heavy_Attack 등)
 6) ComboGroupId - 어떤 Action들과 Combo Chain을 이루는가
 7) ComboIndex - ComboGroup의 몇 번째 Action인가

 * Character, ActionKindId, PlayerActionInputId는 중복 정보이지만 
   런타임 식별 편의를 위해 유지한다.

 * ComboGroupId, ComboIndex는 콤보 계열 식별 및 검증 보조 정보이며,
   실제 전이 허용 여부는 CancelRules에서 결정한다.

B. 시간
 - 얼마나 지속되는가
 - 어떤 시간축으로 해석되는가

 1) Duration - 초 단위 (Hold일 경우 최대 유지시간 개념으로 사용될 수 있음)
 2) 정규화 기준 - 모든 Window는 Normalized로 통일 / 런타임에서는 Secs로 환산 해석
 3) 종료 방식 
  - 기본 종료 정책: 전이 없으면 자연 종료
  - 홀드형 Action은 입력 유지 / 해제 규칙에 따른 별도 종료 정책 적용

 * Loop Action은 지원하지 않는다.
 * Locomotion 계열의 State의 경우 별도로 관리한다.

 EndPolicyDef
  - EndType
  - DefaultNextActionId
  - HoldReleaseBehavior

C. 표현
 - Action의 표현은 별도 Animation 선택 규칙으로 결정한다.
 - 현재는 (ActionId, LocomotionState) -> AnimationId 1:1 대응을 사용한다.
 - ActionDef는 별도 Animation override 데이터를 가지지 않는다.
 - 필요 시 추후 ActionPresentationDef를 추가하여 확장한다.


D. 시작 조건 - RequestRequirementDef[], ResourceCostDef[]
 1) Request Requirements 
  - 이 액션 자체가 요청 후보가 될 수 있는가
  - ex) 현재 금지 상태 여부, 자원 충분 여부 등

  - RequirementType
  - Parameter

 2) Resource Cost - Stamina 등
  - 요청 / 승인 시 필요한 자원과 소비 시점

  - ResourceType
  - Amount
  - ConsumeTiming (ex. 요청 시, 승인 시, 윈도우 진입 시 etc.)


E. 전이 규칙 - TransitionRuleDef
 - 현재 상태에서 요청된 상태로의 전이를 승인할 수 있는가

 1) Interrupt Rules - 외부 이벤트 인터럽트 (피격, 스턴(패링 당함), 사망 등)
	- InterruptCauseType (ex. OnHitReceived, OnParried, OnHpZero etc.)
	- ToActionId : 전이 대상 Action
	- WindowPolicy : Always or Range
	- WindowStartNormalized : Window 허용 시작
	- WindowEndNormalized : Window 허용 끝
	- Priority


 2) Cancel Rules - 현재 액션이 스스로 허용하는 전이
	- ToActionId : 전이 대상 Action
	- CancelKind : 왜 갈 수 있는가 (ex. Combo, HoldRelease, DodgeCancel etc.)
	- WindowPolicy : Always or Range
	- WindowStartNormalized : Window 허용 시작
	- WindowEndNormalized : Window 허용 끝
	- CancelConditionType (optional, 1차 구현 제외) : 입력 외 추가 조건 
	- Priority

 3) Input Buffer Policy - 전이 판정 전 입력 후보를 보존하는 시스템 전역 정책

 * Interrupt는 Cancel보다 우선 평가된다.
 * Priority는 동일 규칙군 내부에서 후보가 여러 개 동시에 만족될 때의 우선순위이다.


F. 동작 세그먼트 - ActionMovementSegmentDef
 - 액션 도중 어떻게 움직이는가

 1) Movement - 수평 이동
 2) Rotation - 회전
 3) Vertical Move - 수직 이동
 4) Direction Policy 
  - 어떤 기준 방향을 따르는가
  - 언제 샘플링 하는가


 - StartNormalized : Segment의 시작
 - EndNormalized : Segment의 끝
 - HorizontalMovementMode : 수평 이동 방식
 - MoveDistance : 이동량
 - RotationMode : 회전 방식
 - RotationRate : 회전량
 - VerticalMoveMode : 수직 이동 방식
 - VerticalAmount : 수직 이동량
 - DirectionPolicy : 방향 기준 정책
 - DirectionSampleTiming : 방향 샘플링 타이밍


G. 전투 판정 - CombatWindowDef
 - 판정 윈도우 활성화는 언제되는가

 1) Active Combat Window 
  - 능동적으로 판정에 참여하는 Window
  - Attack Window, Parry Window 등

 2) Defensive State Window 
  - 특정 피격 반응을 무시하거나, 경직 전이를 제한하는 상태
  - Armor Window, Invulnerability Window 등

 * Defensive State Window는 필요 시 특정 판정 타입에 대한 무효화를 포함한다.


 - WindowType : 윈도우 종류
 - StartNormalized : 윈도우 시작
 - EndNormalized : 윈도우 끝
 - ProfileId : 실제로 무엇을 활성화하는가
 - AppliesTo : 어떤 판정에 적용되는가 (optional) (ex. FrontPhysical, ParryableAttack etc.)


H. 이벤트 - ActionEventDef
 - 부가 효과가 언제 발생하는가

 1) Action Event - 발사체 생성


 - EventType : 이벤트 종류

 - TimeNormalized : 언제 발생하는가
 - PayloadId : 구체 데이터 참조
 - TriggerConditionType : 발동 조건 종류 (ex. Always, OnParrySuccess etc.)


 -------------------------------------------------------------------------------------------------

3. Animation 계열
 - AnimationCollisionDef : AnimationId
	- AnimationCapsuleDef[]
	- AnimationCapsuleFrame[]

A. 식별
 1) AnimationId : 주 식별자 != None
 2) Name : 보조 식별자 != None


B. 기본 메타
 1) Version > 0
 2) Fps > 0
 3) NumFrames > 0


C. 정적 충돌 메타 - AnimationCapsuleDef[]
 - 프레임에 따라 바뀌지 않는 Capsule 정의

 1) BoneIndex 
 2) Radius > 0
 3) Roles[] != None


D. 동적 충돌 포즈 - AnimationCapsuleFrame[]
 - 프레임별 Capsule Pose

 1) FrameIndex < NumFrames
 2) Capsules[] : p0, p1

-------------------------------------------------------------------------------------------------

4. Buff 계열
 - BuffDef : BuffId
	- BuffProfileDef
	- BuffLifetimeDef
	- BuffModifierDef[]
	- BuffApplyRequirementDef[]
	- BuffRemoveRuleDef[]
	- BuffTriggerDef[]


A. 식별 - BuffProfileDef
 - 어떤 버프인가? 어떤 계열인가?

 1) BuffId : 주 식별자 != None
 2) Name : 보조 식별자 != None
 3) BuffKind : 상위 분류 != None
 4) StackGroupId : 중첩 / 대체 여부 > 0
 5) Tags[] : 세부 속성 (Version 1 제외)

B. 수명 - BuffLifetimeDef
 - 얼마나 지속되는가?

 1) enum DurationPolicy
  - 어떤 방식으로 존재하는가

 2) DefaultDurationSec
  - Timed 계열일 때 몇 초 유지되는가

 3) TickIntervalSec (optional)
  - Tick 주기

 4) 중첩 > 0
  - maxStackCount

 5) enum 재적용
  - 이미 존재할 때 다시 받을 경우 무엇이 갱신되는가

 * 버프는 우선 단일 인스턴스 + 스택 모델을 가정한다

C. 효과 - BuffModifierDef[]
 - 이 Buff가 실제로 무엇을 바꾸는가

 1) 무엇을 - Stat, StateFlag, Periodic 3가지로 고정
 2) 어떻게
 3) 얼마나
 4) 언제 (Always, OnTick 정도로 제한)
 5) 조건 (상태 기반 조건만 허용)


D. 부여 조건 - BuffApplyRequirementDef[]
 - 언제 적용 가능한가

 1) RequirementType
 2) Parameter

E. 제거 규칙 - BuffRemoveRuleDef[]
 - 무엇이 이 Buff를 끝내는가

 1) RemoveRuleType
 2) Parameter

F. 트리거 / 부가 이벤트 - BuffTriggerDef[] (Version 1 제외)
 - Buff가 붙어 있는 동안 무엇을 유발하는가
 - 사건 기반 조건 처리

 1) EventType
 2) ActionType
 3) PayloadId (optional)
 4) InternalCooldownSec
 5) MaxTriggerCount


 * Trigger는 동일 프레임 재귀 연쇄를 허용하지 않고,
   최대 체인 깊이를 시스템 전역 정책으로 제한한다.

-------------------------------------------------------------------------------------------------

5. World 계열
 - WorldDef : WorldId
	- WorldTopologyDef
	- WorldEntryPolicyDef
	- MapDef
	- WorldProgressRuleDef
	- WorldLinkRuleDef[]
	- WorldSpawnDef


A. 식별
 - 어떤 월드인가

 1) WorldId : 주 식별자
 2) Name : 보조 식별자


B. 구조 / 유형 - WorldTopologyDef
 - 어떤 종류의 월드인가
 
 1) WorldKind : 컨텐츠 / 운영 (ex. Hub, Dungeon, Field etc.)
 2) InstanceType : 생성 수명 모델 (ex. Persistent, Instanced, SessionScoped etc.)


C. 입장 / 생성, 파괴 정책 - WorldEntryPolicyDef
 - 어떻게 생성, 파괴되는가
 - 최대 인원 등

 1) CreationPolicy : 생성 정책
 2) JoinPolicy : 입장 정책
 3) MaxPlayerCount : 최대 인원
 4) AllowReEntry : 이탈 후 재입장 허용 여부
 5) DestroyWhenEmpty : 빈 월드일 때 파기 가능한가
 6) EmptyDestroyDelaySec (optional) : 빈 상태 유지 후 몇 초 뒤 파기하는가
 7) FallbackWorldId (optional) : 월드 생성, 입장 실패 시 Fallback 정책
    
 * 해당 Fallback은 전역 입장 실패 Fallback 정책을 명시한다.

D. 맵 구성 - MapDef
 - 어떤 맵을 쓰는가
 - 어디에 Entity 배치가 가능한가

 1) MapResourceId
 2) DefaultPlayerSpawnPointId
 3) NamedSpawnPoint[]
 4) NavigationProfileId (optional)
 5) EnvironmentTag[] (optional)


E. 스폰 구성 - WorldSpawnDef
 - 어떤 SpawnSet을 언제 참조하는가

 1) InitialSpawnSetId : 월드 초기 진입 시 참조
 2) RespawnSpawnSetId (optional) : Respawn 시 참조


 * 실제 스폰 규칙은 SpawnSetDef / SpawnEntryDef가 담당한다.


F. 진행 / 완료 규칙 - WorldProgressRuleDef
 - 클리어, 실패 조건
 - 종료 시점

 1) ClearConditionType : 클리어 조건
 2) FailConditionType : 실패 조건
 3) CompletionActionType : 완료 / 실패 후 처리 방식
 4) CompletionDelaySec (optional) : 종료 전 대기 시간
 5) AutoCloseOnComplete : 완료 후 자동 종료 여부


G. 이동 / 연결 규칙 - WorldLinkRuleDef[]
 - 어디로 이동 가능한가
 - 기본 Fallback World는 무엇인가

 1) LinkType : 이동 링크 유형
 2) TargetWorldId : 이동 대상 월드
 3) ConditionType : 이동 가능 조건
 4) ConditionParameter (optional) : 이동 시 파라미터
 5) FallbackWorldId (optional) : 링크 실패 시 Fallback
 6) EntryPointId (optional) : 대상 월드의 어느 진입점을 쓰는가

 * 해당 Fallback은 개별 링크 실패 Fallback 정책을 명시한다.


-------------------------------------------------------------------------------------------------

6. SpawnSet 계열
 - SpawnSetDef : SpawnSetId
	- SpawnEntryDef[]

A. 식별

 1) SpawnSetId : 주 식별자
 2) Name : 보조 식별자

B. 구성 - SpawnEntryDef[]
 - 어떤 Entity를 : CharacterId
 - 어디에 : SpawnPointId
 - 얼마나 : Count
 - 어떤 조건으로 : SpawnConditionType
 - Respawn 여부 : RespawnPolicy / RespawnDelaySec(optional)
