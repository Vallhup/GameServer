

ID 공통 규칙
 1. ID는 데이터와 경로를 가지지 않는다. (순수 식별자 역할)
 2. Definition은 ID만 참조한다.
 3. Registry는 Definition만 소유한다.
 4. Runtime은 Registry를 통해서만 데이터를 조회한다.


--------------------------------------------------------------------

1. Category ID
 - EntityCategoryId
 - FactionId

 
Category 규칙
 1. Category ID는 속성 분류용이다.
 2. Category ID는 Action / Animation lookup Key로 직접 쓰지 않는다.

--------------------------------------------------------------------

2. Contents ID
 - CharacterId
 - AIArchetypeId
 - BuffId


Contents 규칙
 1. Contents ID는 각 Root Definition의 Key다.
 2. 캐릭터 관련 바인딩의 기준 Key는 CharacterId다.

--------------------------------------------------------------------

3. Logic ID
 - ActionId
 - ActionLocalId (Character Local ID)


Logic 규칙
 1. ActionId는 상위 행동 분류이다.
 2. 세부 패턴은 ActionLocalId (Character Local ID)로 분리한다.
 3. policy / profile / animation binding은 같은 Action Key 체계로 묶는다.

--------------------------------------------------------------------

4. Resource ID
 - AnimationId


Resource 규칙
 1. AnimationId는 리소스 참조용이다.
 2. 리소스에서 로직을 역참조하지 않는다.

--------------------------------------------------------------------

5. World ID
 - WorldId
 - SpawnSetId

 
World 규칙
 1. 맵 관련 수치와 경로는 MapDef로 이동한다.
 2. 맵과 캐릭터 연결은 SpawnSet같은 중간 정의를 통해서만 한다.

--------------------------------------------------------------------
