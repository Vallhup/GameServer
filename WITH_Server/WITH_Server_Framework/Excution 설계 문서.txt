1. Simulate
	- Lane : Parallel / 필요 시 제한적 Serial / Main
	- Dispatch : concurrent ready queue
	- Phase 종료 판정 : Simulate phase outstanding counter
		- Simulate phase 시작 전에 전체 node 수를 세고
		  이를 remainingSimulateNodes 초기값으로 둔다
		- 실행 중 증가 X / 단조 감소가 중요함
		- remainingSimulateNodes == 0 -> phase primary 종료


	- 초기화 단계
		1. remainingDeps 초기화
		2. remainingSimulateNodes 초기화
		3. remainaingNodesInScope 초기화
		4. simulatePhaseDone = false
		5. dep count == 0인 simulate node 탐색
		6. NotReady -> Ready -> Queued
		7. queue push

	- worker 루프
		1. queue pop
		2. Queued 상태 재검사
		3. scope 상태 재검사
		4. 실행 가능 시 Queued -> Running
		5. 실행 불가 시 Queued -> Canceled / Skipped
		6. 실행 후 Running -> Succeeded / Failed
		7. sucessor dep 감소
		8. 마지막 dependency 해소자가 successor enqueue 책임 가짐


2. Commit
	- Lane : Serial
	- Dispatch : Serial execution pass


3. LifecycleFlush

* 1차 구현에서 serial phase ordering은 build-time dependency 기반
  stable topological order로 고정

Serial phase 공통 절차
	1. serialExecutionOrder[plan.begin, plan.end) 순회
	2. node state가 NotReady이면 NotReady -> Ready (-> Queued)
	3. scope 상태 재확인
	4. 실행 가능 시 Ready -> Running
	5. 실행 불가 시 Ready -> Canceled / Skipped
	6. 실행 후 terminal 처리
	7. scope counter 감소 및 close candidate signal 게시


Serial phase ordering 저장 형식
	- serialExecutionOrder : ExecNodeId[]
	- commitPlan { begin, count }
	- lifecycleFlushPlan { begin, count }
	- reconcilePlan { begin, count }



phase 내부 topological order를 만드는 절차
	1. phase node 수집
	2. phase 내부 edge 추출
	3. indegree 계산
	4. stable topological sort 수행 (ExecNodeId 오름차순)
	5. 결과를 serialExecutionOrder에 append

buile-time validation
	1. phase 내부 cycle 금지
	2. phase mismatch dependency 처리
	3. 앞 phase 의존은 허용하되 런타임 의존으로 두지 않음


* scope 취소면 남은 serial node를 모두 terminal 처리




Scope 종료 판정 : scope outstanding counter
	- remainingNodesInScope
		- 해당 scope에 속한 node 중 아직 terminal이 아닌 node 수
		- scope 소속 node 수 전체를 초기값으로 두고,
		  그 scope의 node가 terminal로 최초 진입할 때마다 감소
		- Grpah build가 끝난 뒤, 실행 시작 전에 계산
		- remainingNodesInScope == 0 -> Closed 가능



Counter underflow 제한 규칙
	1. 카운터 감소는 오직 terminal state 최초 진입 시점에만 허용
	2. terminal state 간 재전이는 금지
	3. fetch_sub 반환값이 0이면 즉시 assert / fatal



phase close / scope close의 소유권 모델
	1. terminal event 발생
		- scope counter 감소
		- simulate counter 감소
		- old == 1 -> 마지막 종료 감지


	2. close candidate 게시
		- 그 스레드는 직접 close를 완료하지 않고
		  "이 scope/phase는 close 후보임"을 executor에 알림

	3. executor 확정
		- executor가 그 후보를 보고 실제 close를 수행
			- scope state를 Closed로 전이
			- simulate phase 종료 확정
			- 다음 serial phase 진입 결정


scope close 후보 처리 모델
	- node terminal 진입 시 counter.fetch_sub(1)
	- 반환값이 1이면 마지막 node 종료
	- 해당 스레드는 scopeCloseRequested = true 를 set
	- executor가 이후 이 플래그를 보고 scopePhase -> Closed 확정
	- scope close의 본체는 counter, flag는 후처리 트리거


simulate phase close 모델
	- simulate node terminal 진입 시 counter.fetch_sub(1)
	- 반환값이 1이면 마지막 simulate node 종료
	- 그 스레드는 simulatePhaseDone = true 같은 완료 신호 set
	- executor가 이를 보고 Simulate 종료를 확정
	- phase close는 반드시 executor가 확정하도록


close candidate 게시 방법
	1. bool flag per scope / phase 
		- 1차 구현 적용

	2. close queue
	3. epoch / bitmap


executor의 scope close 후보 처리 시점
	1. 즉시 처리
	2. phase 경계에서 처리 (1차 구현 적용)


worker 책임
	1. node 실행
	2. successor 해소
	3. terminal 진입
	4. counter 감소
	5. 마지막 감소 감지
	6. close candidate signal set

executor 책임
	1. close candidate 수집 / 확정
	2. scope phase Closed 반영
	3. simulate phase 종료 확정
	4. 다음 phase 진입

* 1차 구현에서는 executor가 scope close 후보를 늦게 반영해도 괜찮음


Commit 내부 노드 분류
	1. Structural Apply
		- ECS 구조 자체를 바꾸는 반영
			- entity create/destroy
			- component add/remove
			- structural command buffer flush

	2. Deferred State Apply
		- 구조는 이미 정해졌고, 그 위에 지연된 상태 값을 실제 반영
			- deferred component value write
			- runtime cache apply
			- local stat/transform/action state finalize
			- dirty-marked local data materialization

	3. Post-Commit Finalize
		- commit 결과를 정리/봉인해서 다음 phase가 읽을 수 있게 만드는 작업
			- dirty flag finalize / reset
			- local output buffer finalize
			- local event/lifecycle handoff 준비
			- post-commit consistency finalize


LifecycleFlush 내부 노드 분류
	1. LifecycleFlush
		- spawned / despawned signal flush
		- attach/detach lifecycle signal flush
		- disconnected lifecycle signal flush
		- output flush trigger / local lifecycle bridge flush

5. Scratch arena 규약

	1. scratch 종류 분리

			- executor가 frame 시작 시 확보

7. Debug assertion 목록

	1. terminal state에서 다시 CAS 성공하면 fatal
	2. remainingDeps.fetch_sub() == 0 이면 fatal
	3. remainingNodes.fetch_sub() == 0이면 fatal
	4. Queue -> Running은 worker만 가능
	5. Running -> Canceled / Skipped 시도 시 fatal
	6. serial phase node가 phase != expectedPhase이면 fatal
	7. scopePhase == Closed 인에 non-terminal node가 남아 있으면 fatal
	8. simulatePhaseDone == true 인데 remainingSimulateNodes != 0 이면 fatal
	9. build 결과에서 commnit / lifecycle / reconcile plan 구간이 겹치면 fatal
	10. Queued 상태가 아닌 node에 대해 worker가 dequeue 실행을 시도하면 fatal
	11. 마지막 dependency 해소자가 아닌 스레드가 successor ready 전이를 시도하면
	    fatal 또는 debug assert
